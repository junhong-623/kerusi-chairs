# 收录一把椅子

这个仓库是公开投稿入口。网站源码继续放在原来的私有仓库，投稿不会自动
触发部署。第一阶段由维护者手动审核和收录。

## 审核流程

1. 在投稿 Issue 回复「已收到，待审核」。
2. 确认下载链接可访问，并核对模型、贴图来源和展示、分发权限。
3. 下载到本地审核目录。ZIP 只取模型与说明，不运行投稿附带的脚本。
4. 检查 GLB 大小、材质、贴图，以及椅背、椅底是否完整。
5. 在网站本地预览中检查旋转、缩放、自动旋转和加载效果。
6. 准备英语、马来文和中文介绍，保留作者署名、链接和必要的授权说明。
7. 在 Issue 回复「已接受，待收录」，或说明需要修改、未收录的原因。
8. 在网站仓库通过单独的修改加入模型，审核后才发布。
9. 发布后核对线上结果，再在投稿 Issue 回复结果链接并关闭。

审核时可以采用以下状态标签，仓库创建后由维护者按需添加：

| 标签 | 状态 |
| --- | --- |
| `submitted` | 收到投稿 |
| `needs-changes` | 等作者补资料或修改模型 |
| `accepted` | 接受，等待加入网站 |
| `published` | 已核对线上展示 |
| `declined` | 本次不收录 |

## 网站扩展框架

目前网站本地预览仍展示蓝桥椅。投稿仓库不负责模型切换，也不存放部署凭证。
以后给网站接入多把椅子时，每把椅子按同一份资料整理：

```text
chairs/<chair-id>/
  model.glb
  poster.webp
  chair.json
  LICENSE.txt
```

`chair.json` 记录唯一编号、三语名称和介绍、作者与主页、投稿 Issue 链接、
授权类型和来源。可参考 [资料样例](../examples/chair.json)。这是收录资料的
约定；当前网站还没有读取这些文件的多模型选择器。

作者投稿的模型不要被现有蓝桥椅生成脚本覆盖。只有完成审核并进入网站
发布目录的模型，才加入未来的网站椅子列表。

## 维护边界

- GitHub Issue 表单仅检查资料是否填写；文件大小、格式和授权由维护者审核。
- 不根据 Issue 内容自动下载、执行、合并或发布模型。
- 未收录的附件由 GitHub 保管，未直接加入网站构建产物。
- 接受投稿与发布成功是两个状态，发布后才关闭为 `published`。
