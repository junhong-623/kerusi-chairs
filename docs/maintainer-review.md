# 收录一把椅子 — check dulu, publish later.

这个公开仓库负责收投稿。网站已经支持多椅子展览、缩略图切换、统一三语
设置和独立椅子网址；维护者在[网站后台](https://keru.si/admin/)管理草稿和发布。
网站源码仍在私有仓库，收到投稿不会自动下载文件或触发部署。

## 从投稿到展览

1. 打开投稿 Issue，确认名称、故事、作者、下载链接、图片和授权说明齐全。
   在 GitHub 回复收件情况；需要补资料时标为 `needs-changes`。
2. 检查文件来源和实际授权，确认允许 keru.si 托管、展示、分发资产及保留署名。
   可参考[庙会红椅投稿 #1](https://github.com/junhong-623/kerusi-chairs/issues/1)的填写方式。
3. 登录后台，进入「投稿收件箱」，查看原始内容后点「导入为草稿」。这一步
   才会下载可识别的 GitHub 模型和图片；草稿仅管理员可见，授权审核默认未勾选。
4. 核对模型和预览图都已导入。ZIP 先由维护者解压，再手动上传 GLB；其他
   网站链接、无法识别的附件或缺失文件也使用手动上传。只取模型、图片和
   说明，不运行投稿包中的脚本。
5. 核对中文、English、Bahasa Melayu 的名称和介绍，并保留作者与真实授权。
   自动导入不保证资料准确，也不替代翻译。其他故事字段可选。
6. 审核授权后勾选后台的授权确认，点「保存并预览」。检查旋转、缩放、
   空闲自动旋转、背面、椅底和手机尺寸的展示。可上传 1200 × 630 分享封面。
7. 确认收录时，在 GitHub 回复并标为 `accepted`。继续修改已保存草稿不会
   改变原有线上版本。
8. 在后台点「发布到展览」，核对确认框后点「正式发布」。这会更新已发布
   资料，不需要为了收录椅子修改网站源码或重新部署网站。
9. 检查公开 `/chairs/<chair-id>` 页面、椅子切换、三语介绍、署名和分享资料。
   确认后在 GitHub 回复结果链接，标为 `published`，再关闭 Issue。

GitHub 标签和评论仍由维护者手动管理，后台不会自动同步。收件箱的草稿
状态也不能代替查看原 Issue 的审核标签。导入、接受和发布是不同步骤。

## 文件限制与导入方式

| 项目 | 当前要求 |
| --- | --- |
| 公开投稿 GLB | 不超过 **10 MB**，建议小于 **5 MB**。 |
| 后台 GLB 技术上限 | **12 MB**；不提高公开投稿的 10 MB 标准。 |
| 预览图与分享封面 | PNG、JPEG、WebP，每张不超过 **3 MB**。 |
| 模型审查目标 | 少于 100,000 个三角形，贴图不超过 2048 × 2048；由维护者审核。 |
| 资产库 / 椅子数量 | 当前应用上限 **256 MB / 200 把**，包括已存储草稿资产。 |

后台界面 MB 按 1024 × 1024 字节计算。ZIP 按解压后 GLB 的大小检查。
ZIP 文件可以随投稿提交，后台目前不会自动解压或从中提取模型。

自动导入只接受程序允许的 GitHub 文件来源，并按 URL 路径后缀查找 `.glb`
和 `.png`、`.jpg`、`.jpeg`、`.webp`。优先使用 GitHub 的 raw/download 链接。
无法识别的附件网址或其他文件托管服务，审核后下载并手动上传即可。

模型应为包含所有资源的 glTF 2.0 GLB，保留完整靠背和椅底，移除无关场景。
当前使用静态椅子与标准 glTF 材质。后台拒绝需要额外扩展的 GLB、外部
资源引用和 SVG 图片。格式校验通过后，仍需检查实际渲染和授权。

## GitHub 审核标签

| 标签 | 状态 |
| --- | --- |
| `submitted` | 收到投稿，等待审核。 |
| `needs-changes` | 等作者补资料或修改模型。 |
| `accepted` | 已接受，待准备或发布。 |
| `published` | 已核对公开展示，并附结果链接。 |
| `declined` | 本次不收录，回复具体原因。 |

下架椅子会保留后台草稿和资产；若公开状态改变，也应手动更新原 Issue
的标签及说明。已经下载的文件和分享平台缓存不会随下架自动消失。

## 资料结构与存放位置

[examples/chair.json](../examples/chair.json) 对齐当前椅子 schema：
`schemaVersion`、`id`、`number`、`order`、`translations`、`creator`、`license`、
`assets`、`sourceIssue`。它是结构示例，不是要求投稿者写代码，也不是可直接
上传到后台的 JSON 导入文件。

- `translations` 使用 `en`、`ms`、`zh`；每种语言的名称和介绍是发布必填项。
- `license.permissionConfirmed` 默认 `false`，由维护者真实审核后确认。
- `assets` 示例为空。上传后后台分配 `/media/<asset-id>` 路径，不把外部
  下载网址直接用作已发布资产。
- `sourceIssue` 保存投稿编号。自动导入的 ID 为 `chair-issue-<编号>`，创建后固定。
  手动新增可自选 ID，例如 `wooden-stool`。

草稿和发布版本存放在 Cloudflare 的持久化数据库。后台管理上传模型、
图片和分享封面；公开投稿包留在 GitHub 或投稿者提供的文件来源。原来的
蓝桥椅生成脚本只生成种子模型，不会覆盖后台导入的椅子。

## 维护边界

- Issue 表单检查必填资料；模型大小、完整性、来源和授权仍要审核。
- 维护者明确点击导入后才下载文件，不执行投稿附带代码，不自动发布。
- 草稿编辑与线上版本分开，发布前先保存并检查预览。
- 网站源码发布与椅子资料发布分开；增加椅子通常通过后台完成。
- 保留原投稿包和授权记录，数据库持久化不代替离线资料留存。
